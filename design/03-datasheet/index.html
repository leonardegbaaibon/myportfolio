Operating notes

Six practices that produced the numbers above, written as instructions rather than values.

Test on the slow device

A mid-range Android stays in the loop from day one. Simulators lie about battery, thermal throttling and network. Both the Kabu battery result and the NidiDrive load-time result came from the cheap phone.

Assume the connection drops

Idempotent writes, a reconciliation pass on resume, and never letting a spinner be the only state a screen can hold. This is the normal case in the markets these apps ship to, not an edge case.

Instrument before optimising

Sentry, crash grouping and a small set of funnel events go in first. The 68% memory result came from a heap snapshot. Without a measurement, performance work is decoration.

Budget for store review

Provisioning, phased rollout, privacy manifests, rejections. Six Apple submissions and eight on Play means I plan around review rather than discover it in week ten.

Design in the same loop

Figma before the editor, tokens in the repository so the two do not drift. Most measured retention gains came from reworking a flow, not adding a screen.

Write the handover early

Contracts end. Mine end with an architecture note, a deployment runbook, and the next three things I would do in priority order. Talstrike V2 was scoped that way before handover.
